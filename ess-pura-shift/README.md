# ESSプラシフト

Googleフォームへの回答だけで、学期単位のディベートプラ・サマリープラを自動編成する Google Apps Script アプリケーション。

> 全員がGoogleフォームに回答する → 管理者がボタンを1つ押す → その学期のプラが確定する

詳しい仕様は [docs/spec.md](docs/spec.md) を参照。

---

## できること

- Googleフォームをスクリプトから自動生成し、回答送信をトリガーに処理を起動する
- 回答から名簿を自動作成する（管理者が1人ずつ入力しない）
- 月〜土 × 1〜5限の30コマから参加可能コマを取り出す
- ディベートプラとサマリープラを自動編成する（1人につき各1回が目標）
- 1プラを4〜6人に収める
- 男女比をできる限り均等にする
- 各プラへ経験者・役職者を最低1人配置する
- 過去の担当回数が少ない人を優先して負担を均す
- 学期単位でシフトを固定する（仮シフト → 確定シフト）
- 条件を満たせない箇所を警告として一覧化する
- 同じ人を同じコマの2活動へ重複配置しない

## ファイル構成

```
ess-pura-shift/
├── appsscript.json          Apps Script のマニフェスト
├── src/
│   ├── 00_Constants.gs      コマ定義・設定既定値・フォーム設問文（純粋）
│   ├── 10_Solver.gs         編成アルゴリズム（純粋）
│   ├── 11_Validator.gs      検証と警告生成（純粋）
│   ├── 20_Sheets.gs         スプレッドシートの読み書き
│   ├── 30_Roster.gs         フォーム回答の取り込みと名簿更新
│   ├── 40_FormSetup.gs      フォーム生成とトリガー登録
│   ├── 50_Shift.gs          学期シフトの生成・確定・解除
│   └── 90_Menu.gs           メニュー
├── test/
│   └── run-tests.js         Node で走らせる検証
└── docs/
    └── spec.md              仕様書
```

`00`〜`11` は Google のサービスに一切依存しない。アルゴリズムをそこへ閉じ込めてあるので、Apps Script を動かさずに Node でテストできる。`20` 以降がデータの出し入れとUIを担当する。

## 導入手順

1. Googleスプレッドシートを新規作成する
2. 「拡張機能」→「Apps Script」を開く
3. `src/` の各ファイルの内容を、同じ名前のスクリプトファイルとして貼り付ける
   （ファイル名の数字プレフィックスは読み込み順を明示するためのもので、Apps Script 上での順序は問わない）
4. 「プロジェクトの設定」→「`appsscript.json` マニフェストファイルをエディタで表示する」を有効にし、本リポジトリの `appsscript.json` の内容を反映する
5. スプレッドシートを再読み込みすると、メニューに **ESSプラシフト** が現れる
6. メニューから **初期設定** を実行する（シートと既定の設定値が作られる）

`clasp` を使う場合:

```bash
npm install -g @google/clasp
clasp login
clasp create --type sheets --title "ESSプラシフト" --rootDir ./src
clasp push
```

`appsscript.json` は `--rootDir` の直下に置く必要があるため、`clasp` を使うときはリポジトリ直下の `appsscript.json` を `src/` へコピーしてから `push` する。

## 運用手順

| 順 | メニュー | いつ |
| --- | --- | --- |
| ① | フォームを作成 | 学期のはじめに1回。表示されたURLをメンバーへ配布する |
| ② | 学期を作成 | 学期名（例: 2026年度後期）と学期ID（例: 2026-fall）を登録する |
| ③ | 仮シフトを再計算 | 回答が集まる途中で随時。回答送信のたびに自動でも走る |
| ④ | シフトを確定 | 全員の回答が揃ったら。以降その学期は固定される |

補助メニュー:

- **確定を解除** — 確定を取り消して仮シフトへ戻す。加算した担当回数も元に戻す
- **回答を再取り込み** — トリガー設置前に届いていた回答を名簿へ拾い直す
- **回答状況を表示** — 回答済み・未回答の人数と、同姓同名などの確認事項を出す
- **既存フォームを紐づけ** — すでに作ってあるフォームを後から接続する

### 確定後に回答が届いたら

確定シフトは学期中固定するため、自動では再計算しない。新しい回答は名簿にだけ反映され、「警告」シートへ `LATE_RESPONSE` として記録される。シフトへ反映したい場合は **確定を解除** してから再計算し、改めて確定する。

## シート

| シート | 役割 |
| --- | --- |
| `名簿` | 正規化済みのメンバー情報。過去の担当回数もここに持つ |
| `シフト` | 曜日 × 時限のマトリクス。人が読むための表示 |
| `シフト明細` | 配置の生データ。確定処理と再表示はここを読む |
| `警告` | 生成された警告の一覧（重大 → 警告 → 情報の順） |
| `設定` | 学期の状態、人数の上下限、優先度の重み |
| `担当履歴` | 学期ごとの加算内容。確定解除時に正確に取り消すために残す |
| `フォームの回答 1` | フォームが自動生成する生の回答。編集しない |

---

## 設定

`設定` シートで変更できる。コードを触る必要はない。

| 項目 | 既定 | 意味 |
| --- | --- | --- |
| 最小人数 | 4 | これを下回ると人数不足の警告 |
| 最大人数 | 6 | これを上回ると人数超過の警告 |
| 目標人数 | 5 | 必要なプラ数の見積もりに使う |
| 重み_人数 | 3 | 人数逸脱をどれだけ嫌うか |
| 重み_経験者 | 5 | 経験者0人のプラをどれだけ嫌うか |
| 重み_男女比 | 1 | 男女比の偏りをどれだけ嫌うか |
| 重み_活動数 | 2 | 2活動に入れない人をどれだけ嫌うか |
| 重み_公平性 | 1 | 担当回数の偏りをどれだけ嫌うか |
| 反復回数 | 2000 | 局所探索の回数。6分の実行時間上限を超えるなら減らす |
| 再試行回数 | 3 | 初期解を変えて試す回数 |
| 乱数シード | 20260401 | 同じ値なら何度実行しても同じ編成になる |

条件が競合したときに何を優先するかは、この重みで決まる。既定では経験者の充足が最優先で、男女比が最初に譲る。

## テスト

```bash
node test/run-tests.js
```

Apps Script を動かさずに、全 `.gs` ファイルの構文と、純粋層の振る舞いを検証する。

確認している内容:

- ハード制約（参加可能コマ・同一コマの掛け持ち禁止・同一タイプの重複禁止）が
  30人／100人／経験者不足／低可用など各シナリオで破られないこと
- 100人規模でも実行時間が Apps Script の6分制限に収まること
- 経験者0人のプラが重大警告として報告されること
- 席が足りないとき、担当回数の少ない層が優先されること
- 同じ入力・同じシードで再実行すると同じ編成になること
- 名簿の`参加可能コマ`表記が30コマすべてで往復変換できること
- フォーム回答の解析（全角スペースの正規化、チェックボックスのコマ抽出など）

---

## 制限

- Apps Script の実行時間上限は6分。100人規模なら1秒未満で終わるが、
  反復回数を大きく増やす場合は `設定` シートで調整する
- 氏名の名寄せは前後の空白除去と全角半角スペースの統一のみ。
  同姓同名は自動で区別できないため警告として提示する
- 未確定の論点は [docs/spec.md](docs/spec.md) の「未確定事項」にまとめてある
